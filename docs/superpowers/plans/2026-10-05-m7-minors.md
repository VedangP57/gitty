# M7 Deferred Minors Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** close the 15 minors the M6 final review deferred.

**Architecture:** small, independent fixes in the existing app, exec and core modules; no new subsystems. Each fix gets a test that fails first.

**Tech Stack:** Rust, Ratatui, gix, git CLI.

**Spec:** docs/superpowers/specs/2026-10-02-gitty-design.md

## Global Constraints
- Same as M6 (docs/superpowers/plans/2026-10-05-m6-polish.md, Global Constraints); nothing here changes them.
- Text inputs are never remapped; no remap may silently make an action unreachable.
- A stale `index.lock` is removed only on confirmation, only when no git holds it.

## Review Focus
1. Leaving compare restores exactly what was there (range, search, file selection), also mid-walk.
2. A range whose `oldest^..newest` covers more commits than the selected rows says so.
3. Search on 1.5M commits never delays Rows/Files/Detail/Status and never costs per-frame work proportional to the match count.
4. Overlays never replace each other silently; quitting during a foreground job always asks, whatever the key.
5. Line staging stays well under the spec's interactive budget on a large index.

## Tasks
- [ ] **T1 compare and range.**
  - Compare saves the range anchor, the search input and the selected file path; Esc restores them, the file by path once the list arrives, the row by id even mid-walk.
  - A range header adds `· includes K more` when `git rev-list --count oldest^..newest` (empty tree for a root) exceeds the selected row count (`Request::RangeCount` → `Msg::RangeCount`).
  - Tests: b then Esc keeps a V range and a search and the file; leave compare while the walk is still running; the range note for a range across a merge, none for a linear one.
- [ ] **T2 search cost.**
  - `search_label` caches the match rank, recomputed only when the selection or the hit count changes.
  - Search chunks run on their own pool (2 threads), so reader requests never wait behind them.
  - Tests: label rank stays right after n/N and new hits; a routing test that Search goes to the search pool.
- [ ] **T3 input and overlays.**
  - Hunk-handle clicks only on header rows where the handle is drawn (`staged.is_some()`); a column-0 gap click expands up again.
  - The stale-lock Confirm queues behind an open overlay (like Diverged).
  - Ctrl-C with a foreground network job asks like `q`.
  - Binding an action to a fixed key (ctrl-c, ctrl-z, alt-enter) is a config warning.
  - Tree view: when the selected file is hidden under a collapsed directory, the selection moves to the first visible row (and Enter on a directory folds it).
  - The search bar closes on a tab switch or any click outside it.
  - README: conflict wording matches behaviour; difftool note about `--wait` for GUI tools.
  - Tests: one per item, RED first.
- [ ] **T4 stale index.lock.**
  - `git credential-cache--daemon` (and other `--daemon` git helpers) do not count as running git.
  - The offer records the lock's (inode, mtime); `RemoveIndexLock` removes only that same file.
  - Tests: any_live_git table; a lock replaced after the offer is not removed.
- [ ] **T5 staging cost and job runner.**
  - Measure line staging on git/git with the `changes` example; fold the pre-apply guards into one `git ls-files`/`ls-tree` pair per write (no extra status unless the entry is intent-to-add).
  - `Job::wait` stops waiting for stdout after the same grace as stderr.
  - Tests: guard behaviour unchanged (existing tests) plus a test that a stdout holder outliving git does not block `wait`.
