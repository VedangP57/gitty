# M5 Network — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use `- [ ]`.

**Goal:** gitty fetches, pulls and pushes with live progress. It shows prompts for usernames, passwords, passphrases and host keys inside the TUI, can cancel any network job, auto-fetches quietly while focused, and tunes large repos (commit-graph, fsmonitor, untracked cache) with a notice and `gitty untune`.

**Architecture:**
- **gitty-core gains two modules:**
  - `net`:
    - the commands;
    - a progress parser with Desktop's phase weights;
    - a job runner that streams stderr split on `[\r\n]`, runs in its own process group and is cancelled by killing that group;
    - outcome classification;
    - `git push --porcelain` parsing.
  - `tune`: decides which tuning a repo needs, applies it, and reverts exactly what gitty set.
- **The `gitty` crate adds:**
  - an askpass trampoline: the gitty binary re-executed as `GIT_ASKPASS`/`SSH_ASKPASS`, relaying prompts over a private Unix socket;
  - a network thread (one job at a time), with prompt, progress and cancel wiring;
  - an auto-fetch timer;
  - a maintenance thread for commit-graph writes;
  - the `untune` subcommand.

**Pull is two steps.**
1. `git fetch --progress --prune <upstream remote>`. This part shows progress and can be cancelled.
2. `git merge --ff-only @{u}`. This part is local and quick.

If the branches have diverged, a dialog offers merge (`git merge --no-edit @{u}`) or rebase (`git rebase @{u}`). Killing `git pull` mid-merge would leave `index.lock` and a half-done merge; splitting it keeps cancel safe and leaves only the fetch cancellable.

**Tech Stack:** the git CLI for every network call; `std::os::unix::net` for the askpass socket; `libc::killpg` to cancel.

## Global Constraints
- **Spawn rules for every git call:**
  - the resolved git binary;
  - `GIT_TERMINAL_PROMPT=0`;
  - each process runs in a new session (`setsid` in `pre_exec`) and is killed by process group;
  - network commands add `LANG=C LC_ALL=C` so the progress text is parseable.
- **Interactive jobs** (the user pressed `f`/`p`/`P`):
  - `GIT_ASKPASS` and `SSH_ASKPASS` point at the gitty executable;
  - `SSH_ASKPASS_REQUIRE=force`, `DISPLAY=:0` (only when unset), `GITTY_ASKPASS_SOCK=<socket>`;
  - `credential.helper` stays the user's.
- **Background jobs** (auto-fetch):
  - `GIT_SSH_COMMAND='ssh -o BatchMode=yes'` (only when the user has not set `GIT_SSH_COMMAND` or `core.sshCommand`);
  - no askpass variables;
  - an auth failure (`terminal prompts disabled`, `Permission denied`, `Authentication failed`, `could not read Username`) marks the remote "needs auth" and stops auto-fetching it until a manual fetch succeeds.
- **Commands:**
  - `git fetch --progress --prune <remote>`
  - `git merge --ff-only @{u}`
  - `git push --progress --porcelain <remote> <branch>`; adds `-u` when there is no upstream (the remote is `origin`, else the only remote, else refuse).
  - Never `--force`.
  - A detached HEAD refuses pull and push.
- **Progress:**
  - regex `^(?:remote: )?(?P<title>.+?):\s+(?:(?P<pct>\d{1,3})% \((?P<cur>\d+)/(?P<tot>\d+)\)|(?P<count>\d+))`;
  - weights — fetch: Compressing 0.1, Receiving 0.7, Resolving 0.2; push: Compressing 0.2, Writing 0.7, Resolving 0.1;
  - the displayed fraction never decreases;
  - updates are throttled to one message per 16 ms.
- **Secrets:** a prompt answer exists only in the askpass reply. It is never logged, put in a toast, error detail or `Debug` output, or kept after the reply. The socket lives in a fresh `0700` directory, and the helper exits non-zero on cancel.
- **Auto-fetch:**
  - every `auto_fetch_minutes` (default 5; 0 disables), only while focused;
  - never while another network job runs;
  - failures other than auth stay quiet (shown only in the top bar).
- **Auto-tuning:**
  - only when `auto_tune` is on and the repo is not bare;
  - never overrides a key the user set (any value, at any config level);
  - the keys gitty sets are recorded in local config `gitty.tuned`;
  - `gitty untune` unsets only those keys;
  - thresholds:
    - commit-graph when the history has ≥ 10,000 commits and the graph is missing or does not contain HEAD;
    - fsmonitor and untrackedCache when the index has ≥ 20,000 entries.

## Review Focus
1. **Secrets never leak:**
   - not into logs, toasts, error details, `Debug` or a panic message;
   - the socket is private to the user;
   - Esc on a prompt makes git fail cleanly, not hang.
2. **Cancel really stops:**
   - the whole process group dies, including ssh and remote helpers;
   - no zombies are left;
   - the UI says "cancelled", not "failed" or "done";
   - nothing local is left half-written (only fetches are cancellable).
3. **Auto-fetch:**
   - never prompts and never steals focus or the selection;
   - never runs concurrently with a user's job or while unfocused;
   - stops for a remote that needs auth.
4. **Progress parsing:**
   - copes with CR-only updates, `remote:` prefixes, unknown phases, non-ASCII remote messages and a missing total;
   - never shows a fraction going backwards or above 100%.
5. **Auto-tune:**
   - never overrides explicit user config;
   - never touches bare repos;
   - `untune` reverts exactly what gitty set;
   - a slow commit-graph write never blocks the UI or the writer thread.

## Tasks
- [ ] **T1 net core** (`crates/gitty-core/src/net.rs`).
  - **API:**
    - `Progress::parse_line(&str) -> Option<(String, Option<(u64,u64)>)>`;
    - `Weights::{FETCH, PUSH}`;
    - `Tracker::update(line) -> Option<f32>` (monotonic, phase-weighted);
    - `NetCmd::{Fetch{remote}, FfMerge, Merge, Rebase, Push{remote, branch, set_upstream}}`;
    - `Job::spawn(&GitCli, NetCmd, Mode::{Interactive{sock}, Background}) -> Job`;
    - `Job::cancel_handle() -> Cancel` (pgid), with `Cancel::cancel()` doing `killpg` SIGTERM then SIGKILL after 2 s;
    - `Job::wait(on_line) -> Outcome::{Ok{summary}, Cancelled, Diverged, Rejected{refs}, NeedsAuth, Failed{stderr}}`;
    - `parse_push_porcelain(stdout)`.
  - **Tests:**
    - progress parsing table: CR-only lines, `remote:` prefix, counts without totals, unknown titles, 100% lines;
    - monotonic tracker;
    - fixtures with a local bare remote:
      - fetch brings new commits;
      - ff merge;
      - diverged → `Diverged`;
      - push updates the remote;
      - a non-fast-forward push → `Rejected`;
      - push with `set_upstream` sets `branch.<b>.merge`;
    - cancel: a remote `ext::sh -c "sleep 30"` (`-c protocol.ext.allow=always`) is killed within 3 s and no process in its group survives;
    - background auth failure: an `ext::sh -c "echo 'fatal: could not read Username for …: terminal prompts disabled' >&2; exit 128"` remote → `NeedsAuth`;
    - the stderr classification table as a unit test.
- [ ] **T2 askpass trampoline** (`crates/gitty/src/askpass.rs`, `main.rs` dispatch).
  - **Helper mode:** when `GITTY_ASKPASS_SOCK` is set and gitty is run with one prompt argument:
    1. connect;
    2. send the prompt as a length-prefixed frame;
    3. read the reply frame;
    4. print the answer plus `\n` to stdout and exit 0;
    5. or exit 1 on cancel or error.
  - **Server:**
    - `AskServer::start() -> (AskServer, path)` creates a fresh `0700` temp dir and a socket;
    - an accept thread sends `Msg::Ask{id, prompt, kind: Ask::{Text, Secret, YesNo}}`;
    - `AskServer::answer(id, Option<String>)`;
    - the directory is removed on drop.
  - **Classification:**
    - `Username` → Text;
    - `Password`, `passphrase`, `PIN` → Secret;
    - `(yes/no` or `fingerprint` → YesNo;
    - anything else → Secret (the safe default).
  - **Tests:**
    - classification table;
    - round trip through the real binary (`CARGO_BIN_EXE_gitty`) with a test server answering;
    - real git: `git credential fill` with `GIT_ASKPASS=<gitty>` and no helper returns `username=`/`password=` from the server;
    - cancel → helper exit 1 and `credential fill` fails;
    - `Debug` of the answer type redacts.
- [ ] **T3 wiring and UI.**
  - **Requests, messages and threads:**
    - `Request::Net{op: NetOp::{Fetch, Pull, Push, PullMerge, PullRebase}, background: bool}` on a new single-thread net pool;
    - `Msg::NetProgress{label, fraction}` (throttled);
    - `Msg::NetDone{op, outcome}`;
    - `Msg::Ask{..}`.
  - **App:**
    - a `net: Option<NetJob{label, fraction, cancel}>`;
    - the top bar shows `Fetching origin 42% · x cancel`, then after done "fetched just now";
    - Refs and Status are refreshed after done;
    - `Overlay::Prompt{id, prompt, kind, editor}` is masked for Secret; Enter answers, Esc cancels; for YesNo, `y`/`n`;
    - `Overlay::Diverged` offers `m` merge, `r` rebase, Esc cancel;
    - a rejected push opens a toast with "pull first" and the detail;
    - `x` cancels the running job;
    - `f`/`p`/`P` start jobs; one already running gives the toast "Wait for <label> (x cancels)".
  - **Tests (app, with real local remotes through exec):**
    - `f` fetches and refreshes refs;
    - `p` fast-forwards;
    - a diverged pull opens the dialog and `r` rebases;
    - `P` pushes and sets the upstream;
    - `x` during a hanging fetch reports cancelled;
    - prompt overlay keys (masked render snapshot shows `•••`, never the text);
    - rejected push toast;
    - render snapshot of the progress bar.
- [ ] **T4 auto-fetch.**
  - **Behaviour:**
    - `App::auto_fetch_deadline()` is part of `next_deadline` only while focused, with `auto_fetch_minutes > 0`, an upstream remote not marked needs-auth, and no job running;
    - on tick it queues `Net{Fetch, background: true}`;
    - background progress is not shown (the top bar says "fetching…");
    - `NeedsAuth` marks the remote, the top bar shows `origin needs auth · f`, and auto-fetch stops;
    - a manual `f` that succeeds clears the mark.
  - **Tests:**
    - the deadline appears only when focused and idle;
    - a fake clock fires it;
    - needs-auth stops it;
    - a manual success clears it;
    - auto-fetch never touches the selection or focus.
- [ ] **T5 auto-tuning** (`crates/gitty-core/src/tune.rs`, maintenance thread, `untune`).
  - **API:**
    - `Tune::plan(&Repo, history_len, index_entries) -> Vec<Action::{CommitGraph, Fsmonitor, UntrackedCache}>`;
    - `Tune::apply(&GitCli, &[Action])`, where config actions use `git config --local` and record `gitty.tuned`;
    - `Tune::untune(&GitCli) -> Vec<String>` (keys removed);
    - commit-graph runs `git commit-graph write --reachable --changed-paths` on the maintenance thread, again after a fetch/pull/commit when HEAD is not in the graph, and at most once per 10 minutes.
  - **App:**
    - after the first full walk and status, request `Tune` when `auto_tune` is on;
    - a one-line toast: "Tuned for size: commit-graph, fsmonitor, untracked cache · run `gitty untune` to undo".
  - **CLI:** `gitty untune [path]` prints what it reverted.
  - **Tests:**
    - plan thresholds (with the thresholds lowered for the test);
    - a user-set `core.fsmonitor=false` is never touched;
    - bare repo → empty plan;
    - apply then untune restores the original config exactly;
    - the commit-graph is written and then contains HEAD;
    - `gitty untune` output.
