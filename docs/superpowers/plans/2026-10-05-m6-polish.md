# M6 Polish — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use `- [ ]`.

**Goal:** M6 finishes the spec's UX:
- search, multi-commit ranges, compare-to-branch, the file tree view, and external tools ($EDITOR, difftool);
- the remaining mouse behaviours;
- keymap overrides with a help screen that shows the real bindings;
- the M4/M5 deferred fixes a person would notice;
- benchmarks that fail when a budget is broken, and a README.

**Architecture:**
- **gitty-core:**
  - `search`: a matcher, and path filtering through `git log -- <path>`, which uses commit-graph bloom filters;
  - `Handle::diff_commits(a, b)` for merge-base diffs;
  - `compare` (ordered `rev-list --left-right`);
  - the tune, net and stage hardening.
- **The `gitty` crate:**
  - search state and a search bar;
  - range selection;
  - compare mode;
  - a tree view for the file list;
  - a `Keymap` translation layer in front of `handle_key`;
  - an external-command runner that suspends and restores the terminal;
  - the fix batches.
- **Nothing new in the threading model:** search chunks run on the reader pool; compare and range file lists reuse `Request::Files` with a new `FilesOf` source.

**Tech Stack:** as before; no new dependencies.

**Spec:** docs/superpowers/specs/2026-10-02-gitty-design.md, mainly:
- §11.2 history (multi-select, compare, search, tree view)
- §11.4 keys (and "all bindings are remappable in config")

- §14 config

Deferred minors: the M4 and M5 final reports.

## Global Constraints
- **Search:**
  - `/` opens a one-line bar at the bottom. Text matches summary, author name and email, case-insensitive unless the query has an uppercase letter (smart case).
  - `path:<p>` (combinable with text) keeps commits that touch `<p>`, a literal path or directory prefix.
  - Matches are found in history order. The selection jumps to the first match at or after the current row, and the list is not filtered.
  - `n`/`N` move to the next/previous match, wrapping around. The bar shows `k/N` plus `searching… x%` while scanning.
  - Esc clears the search; a new query cancels the old one by generation.
  - Scanning runs in chunks of 20,000 rows on the reader pool, and the UI never waits on it.
- **Range:**
  - `V` anchors at the selected commit; `j`/`k` extend; Shift-click extends; Esc or `V` ends the range.
  - The files and diff are `oldest^..newest` (the empty tree for a root commit). The header says `N commits · <oldest>..<newest>` with combined `+A −D`.
  - Ctrl-click acts like Shift-click (ranges are contiguous).
- **Compare (`b`):**
  - a fuzzy picker over local and remote branches (subsequence match, ranked by score then name);
  - Enter enters compare mode and the history pane title becomes `Compare with <ref>`;
  - three tabs, switched with `h`/`l` (←/→) while the history pane is focused:
    - Behind (N): in `<ref>`, not in HEAD;
    - Ahead (M): in HEAD, not in `<ref>`;
    - Files: the `merge-base(HEAD, ref)..ref` diff;
  - Esc leaves compare mode and restores the previous selection.
- **Tree view (`t`):**
  - the file list is grouped by directory, with directory rows `▾ dir/` indented by depth;
  - Enter or click on a directory collapses or expands it;
  - the setting persists in UI state.
- **External tools:**
  - The TUI suspends: it leaves the alternate screen and raw mode. The tool runs with inherited stdio, then the terminal is restored even if the tool fails or the user presses Ctrl-C.
  - Paths are passed as arguments, never through a shell. `$EDITOR`/`$VISUAL` and `difftool` are split with shell-like quoting rules, but not run by a shell.
  - **Double-click** a file or diff line → `$EDITOR +<line> <path>` (worktree path; History opens the current worktree file).
  - **`O`** → `difftool <old> <new>`, with the blobs written to temp files named after the path and removed afterwards. The tool is the config's `difftool`; when none is set, a toast says to set one (gitty does not fall back to `git difftool`).
- **Mouse completions:**
  - In the Changes diff, the hunk header's first column is a handle: clicking it toggles the hunk.
  - A gutter drag auto-scrolls when the pointer reaches the first or last row.
  - In split view, Space and gutter clicks stage the side under the pointer, or the side of the cursor column: the left side is deletions, the right side additions.
- **Keymap:**
  - `[keys]` in config.toml maps action names to key strings (`"ctrl-d"`, `"shift-tab"`, `"g"`, `"F5"`, `"enter"`).
  - A remapped action leaves its default key unbound. A key bound to two actions, or an unknown action or key, is a config warning (toast at startup), and the first binding wins.
  - Text inputs (commit box, prompt, search bar) are never remapped.
  - The help overlay is generated from the effective keymap.
- **Benchmarks:**
  - `bench/run.sh` exits non-zero when a §8 budget is missed, printing the budget and the measured value.
  - A criterion bench renders a 220×60 frame (history plus diff) and checks it against < 16 ms.
- **README.md:**
  - install (cargo), usage, the full key table (generated from the keymap, kept in sync by a test), config reference, themes, `gitty untune`, and the performance table;
  - no claims the benchmarks do not support.

## Review Focus
1. **Search on a 1.5M-commit history:**
   - the UI stays responsive and stale generations are dropped;
   - `n`/`N` while scanning move only among the matches found so far;
   - non-ASCII text and smart case behave;
   - `path:` with spaces or glob characters is literal.
2. **Keymap:**
   - no remap silently makes an action unreachable or captures typing in text inputs;
   - help and README show the real bindings.
3. **Range and compare diffs:**
   - correct for merges, root commits and renames;
   - an old file list never replaces a newer selection;
   - leaving compare restores exactly what was there.
4. **External tools:**
   - restore the terminal on every exit path;
   - quoting and paths cannot inject shell commands;
   - temp files are removed and never written into the repo.
5. **The deferred fixes keep M4/M5 safety:**
   - HEAD checks refuse rather than stage onto a moved HEAD;
   - a stale `index.lock` is removed only on confirmation and only when no git process runs;
   - the Trash fallback never loses a file silently;
   - quitting during a push asks first.

- [ ] **T6 network and prompt fixes (M5 minors).**
  - **Push and prompts:**
    - rejected-push advice switches on the porcelain summary (`fetch first`/`non-fast-forward` vs `remote rejected`/hook declines);
    - Esc on a prompt reports "cancelled at the prompt", not "refused";
    - a prompt overlay and any queued prompts close when their job ends.
  - **Cancel and the job runner:**
    - cancel races: `Cancelled` only when the job really died of the signal; the SIGKILL follow-up skips groups that have already exited;
    - a stderr holder that outlives the group cannot block the net thread: a reader thread, plus a 1 s grace period after the leader exits on cancel;
    - quitting while a job runs asks "<label> is running: quit and cancel it? y/n".
  - **Background, overlays and paste:**
    - background fetch failures show `auto-fetch failed` in the top bar, with details on `!`; a cancelled background fetch says so;
    - the Diverged dialog queues behind an open overlay instead of replacing it;
    - pasted prompt text is zeroed, and `Editor`'s Debug prints only the length.
  - **Tune:**
    - `core.commitGraph=false` and shallow repositories get no graph;
    - a graph is reported only if it now contains HEAD;
    - rewrites use `--split`;
    - `untune` skips keys whose value is no longer `true`;
    - a failed record unsets the key it just set;
    - a merge or rebase pull re-checks tuning.
  - **Tests:** one per item, RED first.
- [ ] **T7 staging and status fixes (M4 minors).**
  - **Staging guards:**
    - intent-to-add files: line staging works; the index entry is treated as the empty blob;
    - SetStaged and WriteFile refuse when `HEAD:<path>` no longer matches `entry.head_blob`;
    - `UndoCommit{expect}` refuses unless HEAD is still the commit gitty made, and is offered only when that commit is not on the upstream (spec §12.3);
    - after `apply --cached`, the index blob is checked against the target; on a mismatch, report it with the details.
  - **Submodules:** a submodule entry shows a card (`Submodule <path>: <old>..<new>`) instead of a gix error.
  - **Status and watching:**
    - IndexMark is noted on the worker just before status spawns;
    - linked worktrees also watch the common git dir for refs;
    - a status worker panic answers the status request with an error.
  - **`index.lock` and Trash:**
    - a write failing on `index.lock` checks for running git processes (`pgrep -x git`), and if there are none offers "Remove the stale .git/index.lock?" (Confirm → `WriteOp::RemoveIndexLock`);
    - when the Trash is not writable, copies go to `~/.local/state/gitty/trash/` and the toast says where.
